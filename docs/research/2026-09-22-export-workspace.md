# 검색 결과 엑셀 저장과 화면 이동 개선

목표: 받은 검색 결과를 전체/선택 키워드별로 .xlsx 저장하고, 여러 키워드를 오갈 때 결과를
찾아 페이지 끝까지 이동하는 불편을 없앤다. 선택 단위는 사용자에게 선택지를 제시했고,
별도 응답 전 기본안인 키워드별 묶음을 적용한다.

- 검색·상태·저장 도구 상단 고정, 결과를 키워드 목록 위에 배치한다.
- 최근 본 키워드 8개로 이동하며 기존 결과 확인은 추가 수집을 하지 않는다.
- 키워드 목록은 선택 시 접고 도구 버튼으로 다시 펼칠 수 있다. 상품 영역은 독립 스크롤.
- 엑셀은 현재 받은 키워드 모두 또는 체크한 키워드만 저장한다. 요약/상품/연관어/자동완성/
  도매꾹 5개 시트, 조회 중·실패·미확인 상태를 구분한다. 숫자 0과 빈값을 구분한다.
- 새 검색에서 받은 상품은 전량, 과거 요약 데이터는 보유한 상위 상품만 저장한다.
  저장은 재검색·SSH 없이 화면 데이터로 생성한다. 브라우저 새로고침 시 선택은 초기화된다.
- 새 라이브 결과는 화면 내 기억에 보관해 키워드 이동 때도 전량 상품을 유지한다.

## 테스트 계획

- API→실제 .xlsx 재열기로 한글/숫자/시트/선택 범위/상태/수식 형태 문자열을 검증한다.
- 경계: 선택 0/1/499/500/501개, 상품·검색어 199/200/201개, 키워드 길이 59/60/61,
  비정상 구조·중복, 접근 비밀번호, 요청 크기 제한을 확인한다.
- 실제 Chrome에서 전체/선택 다운로드를 열어 키워드와 상품 행을 확인한다.
- 브라우저 상태 전이: 새 검색→부분 결과→완료, 체크 유지, 기존 키워드 왕복,
  새 요청 중 이전 응답 도착, 실패한 저장 뒤 재시도, 빈 데이터에서 버튼 비활성.
- 1280px/390px 화면에서 도구 고정·결과 위치·목록 접기·최근 키워드 이동·가로 넘침을 확인한다.
- 기존 진행형 UI/웹 단위 회귀를 실행한다. 네트워크 대역은 검색 API 경계에만 두고,
  엑셀 API와 파일 생성은 실제 구현을 사용한다. 쿠팡 재수집은 필요하지 않아 하지 않는다.
- 실제 Excel 데스크톱 앱의 열기는 환경에 없으면 생략하고 .xlsx 재열기 검증으로 기록한다.

구현 참고: [openpyxl 공식 tutorial](https://openpyxl.readthedocs.io/en/stable/tutorial.html).

## 검증 결과

| 계층 | 결과 | 확인 범위 |
|---|---|---|
| 웹 단위·API 통합 | 37/37 통과 (신규 10) | 실제 xlsx 재열기, 0/빈값, 실패 상태, 인증, 입력 경계 |
| 배포 호환 환경 | 맥미니 Python 3.14에서 같은 37/37 통과 | Flask 3.0.3/openpyxl 3.1.5 |
| 브라우저 시스템 | 기존 진행형 UI + 신규 저장/이동 시나리오 통과 | 실제 Chrome, 검색 API만 대역, 엑셀 API는 실제 |
| 화면 | PC 1280px / 모바일 390px 통과 | 상단 도구·결과 위치·표 스크롤·가로 넘침 없음 |
| 결함 변이 | 3/3 감지 | 수식 문자열 처리 제거, 빈 선택 허용, 가격 0 누락 |

선택 1개/2개와 전체 12개를 실제 다운로드 후 열어 범위를 확인했다. 새 검색의 상품 60개를
키워드 왕복 후에도 보존하고, 진행 중 펼친 검색어·상품 스크롤·엑셀 체크를 다음 응답에서
유지한다. 이전 검색의 늦은 완료가 현재 선택 화면을 덮거나 스크롤을 이동시키지 않는다.
조회된 키워드 보기/엑셀 저장에서는 검색 POST가 늘지 않는 것을 확인했다.

증거: 맥미니 `state/export-ui-work/web/ui-export-artifacts/`의 xlsx와 PC/모바일 스크린샷.
로컬 스크린샷: `state/export-desktop.png`, `state/export-mobile.png` (Git 제외).
보지 않은 범위: Excel 데스크톱 앱 직접 실행, Firefox/Safari, 500키워드 실사용 대용량 UX.
추가 쿠팡 수집 없이 검증했다. 생성기는 최대 500키워드, 요청 8MiB를 허용한다.
